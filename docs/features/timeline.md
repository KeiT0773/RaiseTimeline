## 2. 概要

投稿を新しい順に並べて表示するアプリのトップ画面（SC-03）の機能。「すべて」と「フォロー中」の 2 つのタブを持つ。

| ID | 機能名 | 画面 |
| --- | --- | --- |
| F-05 | タイムライン表示（すべて） | SC-03 |
| F-06 | ページング | SC-03（SC-05 の投稿一覧、SC-07 の検索結果でも同じ方式） |
| F-07 | 件数表示（いいね数・コメント数） | SC-03, SC-04, SC-05 |
| F-21 | タイムライン切り替え（すべて / フォロー中） | SC-03 |

## 3. 業務ルール

- 「すべて」には全ユーザーの投稿を、「フォロー中」にはフォローしているユーザーの投稿と **自分の投稿** を表示する。
- 並び順はどちらも投稿日時の新しい順（同じ日時なら投稿 ID の大きい順）。
- インプレッション数・リポスト数は表示しない。

## 4. 機能詳細

### F-05 タイムライン表示（すべて）

- 表示項目（1 投稿あたり）
  - アイコン（[profile.md](profile.md) 3.）、表示名、@ユーザー名、投稿日時（相対表示：「3分前」「2時間前」、1 日以上前は日付）
  - 本文（改行を反映、HTML はエスケープ。画像のみの投稿では本文の行を出さない）
  - 添付画像（ある場合のみ。[post.md](post.md) F-17）
  - 💬 コメント数、♡ いいね数（F-07）
  - 自分の投稿の場合のみ [削除]
- **アイコン・表示名・@ユーザー名をクリックすると、その投稿者のプロフィール（SC-05）へ移る**。そこからフォローできる（[follow.md](follow.md) 2.1 経路 2）。クリックできる範囲はアイコンと名前の部分だけにし、本文のクリック（SC-04 へ移る）とぶつからないようにする
- 投稿が 0 件の場合は「まだ投稿がありません」と表示する

### F-06 ページング

- 1 回に 20 件を表示し、一覧の末尾の [さらに読み込む] で次の 20 件を下に足す
- 次の投稿がない場合は [さらに読み込む] を表示しない
- 読み込みの途中に新しい投稿が増えても、同じ投稿が 2 回表示されないようにする（2 回目以降は「最後に表示した投稿より古いもの」を取る方式。[ER図・テーブル定義](../04_er_diagram.md) 3.）

### F-07 件数表示

- 各投稿にいいね数とコメント数を表示する。0 件のときも「0」と表示する
- いいね・コメントを自分が操作したときは、画面の件数をすぐに更新する（[like.md](like.md)、[comment.md](comment.md)）
- 件数の取得で N+1 問題を起こさない（1 ページ分をまとめて取得する）

### F-21 タイムライン切り替え（すべて / フォロー中）

- タイムラインの上部に「すべて」「フォロー中」の 2 つのタブを表示する。初期表示は「すべて」
- 選択中のタブは URL のクエリで保持する（`/` = すべて、`/?tab=following` = フォロー中）。再読み込み・ページングしてもタブが維持される
- 表示形式・並び順・ページング・件数表示は「すべて」と同じ
- 「フォロー中」で投稿が 0 件の場合は「フォロー中のユーザーの投稿はまだありません。」と表示し、その下に [ユーザーを探す] リンク（SC-07 へ）を出す
- 投稿フォームはどちらのタブでも表示する。投稿後は現在のタブの先頭に自分の投稿が表示される

## 5. 入力制約

入力項目なし（投稿フォームは [post.md](post.md) を参照）。`tab` クエリが `following` 以外の値なら「すべて」として扱う。

## 6. 関連する画面・API・テーブル

| 種別 | 対象 |
| --- | --- |
| 画面 | SC-03 タイムライン画面 |
| API（案） | `GET /api/posts?tab=all\|following&before=<最後の投稿 ID>`（20 件。各投稿に件数・自分がいいね済みか・画像の URL を含める） |
| テーブル | posts, users, likes, comments, post_images, follows |

## 7. 権限

| 操作 | 未ログイン | ログイン中 |
| --- | --- | --- |
| タイムライン閲覧（両タブ） | × | ○ |

## 8. エラーと表示

| 状況 | 表示 |
| --- | --- |
| 取得に失敗した（サーバー停止・通信断） | 一覧の位置に「タイムラインを読み込めませんでした。」と [再読み込み] |
| [さらに読み込む] に失敗した | 一覧の末尾に「読み込めませんでした。」と表示し、[さらに読み込む] を押し直せるようにする |

## 9. 受け入れ基準

| 対象 | 確認方法 | 合格条件 |
| --- | --- | --- |
| F-05 | 複数のユーザーで投稿してからタイムラインを開く | 全員の投稿が新しい順に並ぶ。自分の投稿にだけ [削除] がある |
| F-05 | 投稿者の表示名をクリックする | その投稿者のプロフィール（SC-05）が開く。投稿詳細には移らない |
| F-05 | 本文に `<script>alert(1)</script>` を含む投稿を表示する | 文字としてそのまま表示され、スクリプトは実行されない |
| F-06 | 投稿を 45 件作ってタイムラインを開き、[さらに読み込む] を 2 回押す | 20 件 → 40 件 → 45 件と増え、45 件で [さらに読み込む] が消える。重複する投稿は無い |
| F-06 | 20 件表示した状態で、別のユーザーが新しく投稿してから [さらに読み込む] を押す | 21 件目以降に重複が出ない |
| F-07 | いいね 3 件・コメント 2 件の投稿を表示する | ♡ 3、💬 2 と表示される |
| F-07 | 20 件を表示するときの SQL の発行回数をログで確認する | 投稿の件数に比例して増えない |
| F-21 | 「フォロー中」タブを押す | URL が `/?tab=following` になり、フォロー中のユーザーと自分の投稿だけが表示される |
| F-21 | 「フォロー中」を開いた状態で再読み込みする | 「フォロー中」のまま表示される |
| F-21 | 誰もフォローしておらず自分の投稿も無い状態で「フォロー中」を開く | 案内文と [ユーザーを探す] リンクが表示され、リンクで SC-07 が開く |
