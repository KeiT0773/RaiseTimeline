## 2. 概要

利用者がアカウントを作成し、メールアドレスとパスワードでログインする機能。ログインしていない利用者は、ログイン画面と新規登録画面以外を見られない。

| ID | 機能名 | 画面 |
| --- | --- | --- |
| F-01 | 新規登録 | SC-02 |
| F-02 | ログイン | SC-01 |
| F-03 | ログアウト | 共通ヘッダー |
| F-04 | アクセス制御 | 全画面 |

## 3. 業務ルール

- 1 つのメールアドレスで作れるアカウントは 1 つ。ユーザー名（@ID）も全体で一意。
- パスワードはハッシュ化（BCrypt）して保存し、平文では保存しない。画面・ログ・API の応答にも出さない。
- ログイン状態はセッション（Cookie）で保持する。ブラウザを閉じても一定期間（14 日）はログイン状態を保ってよい。
- ログイン中の利用者が SC-01・SC-02 を開いた場合は、タイムライン（SC-03）へ移す。

## 4. 機能詳細

### F-01 新規登録

- 入力：ユーザー名（@ID）、表示名、メールアドレス、パスワード、パスワード（確認）
- ユーザー名は先頭の `@` を入力しない（入力欄の前に `@` を表示しておく）。大文字と小文字は区別せずに一意とし、保存は入力どおりにする（例：`Hanako` がいると `hanako` は登録できない）
- メールアドレスは前後の空白を除き、小文字にそろえて保存する
- ユーザー名・メールアドレスが既に使われている場合は、該当項目の下にエラーを表示する
- 登録に成功したら、そのままログイン状態にしてタイムライン（SC-03）へ移す
- 自己紹介は登録時には入力しない（プロフィール編集で設定する。[profile.md](profile.md)）

### F-02 ログイン

- 入力：メールアドレス、パスワード
- 失敗時は「メールアドレスまたはパスワードが正しくありません」と表示する（どちらが誤りかは伝えない）
- 成功時は、ログイン前に開こうとしていた画面があればそこへ、なければタイムライン（SC-03）へ移す

### F-03 ログアウト

- 共通ヘッダーの [ログアウト] を押すと、確認なしでセッションを破棄し、ログイン画面（SC-01）へ移す
- ログアウト後にブラウザの「戻る」で前の画面を開いても、データは表示されずログイン画面へ移る

### F-04 アクセス制御

- 未ログインで SC-01・SC-02 以外の URL を開いたら、ログイン画面へ移す（開こうとした URL を覚えておき、ログイン後にそこへ戻す）
- 未ログインで API を呼んだら、401 を返す。画面は 401 を受け取ったらログイン画面へ移す
- 状態を変える API（POST / PATCH / DELETE）は CSRF のトークンを確かめる

## 5. 入力制約

| 項目 | 制約 | エラーの文言（例） |
| --- | --- | --- |
| ユーザー名 | 必須、半角英数字とアンダースコア、3〜15 文字、一意 | 「ユーザー名は半角英数字と _ で 3〜15 文字にしてください」「このユーザー名は既に使われています」 |
| 表示名 | 必須、1〜30 文字（前後の空白を除いて判定。空白のみは不可） | 「表示名を入力してください」「表示名は 30 文字以内にしてください」 |
| メールアドレス | 必須、メール形式、一意 | 「メールアドレスの形式が正しくありません」「このメールアドレスは既に登録されています」 |
| パスワード | 必須、8〜72 文字（BCrypt が扱える上限が 72 バイトのため） | 「パスワードは 8 文字以上にしてください」 |
| パスワード（確認） | パスワードと一致 | 「パスワードが一致しません」 |

## 6. 関連する画面・API・テーブル

| 種別 | 対象 |
| --- | --- |
| 画面 | SC-01 ログイン画面、SC-02 新規登録画面、共通ヘッダー |
| API（案） | `POST /api/auth/signup`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`（ログイン中の利用者の情報。画面の初期表示で使う） |
| テーブル | users |

## 7. 権限

| 操作 | 未ログイン | ログイン中 |
| --- | --- | --- |
| 新規登録・ログイン | ○ | ×（SC-03 へ移す） |
| ログアウト | — | ○ |

## 8. 受け入れ基準

| 対象 | 確認方法 | 合格条件 |
| --- | --- | --- |
| F-01 | 正しい値で新規登録する | タイムラインが表示され、ヘッダーに自分の表示名と @ユーザー名が出る |
| F-01 | 既に使われているユーザー名（大文字と小文字だけ違うものを含む）・メールアドレスで登録する | 登録されず、該当項目の下にエラーが表示される |
| F-01 | 各項目を制約の外の値（2 文字のユーザー名、7 文字のパスワードなど）にして登録する | 登録されず、該当項目の下にエラーが表示される |
| F-01 | 登録後、DB の users を確認する | パスワードが平文ではなく BCrypt のハッシュで保存されている |
| F-02 | 誤ったパスワード、存在しないメールアドレスでそれぞれログインする | どちらも同じ文言「メールアドレスまたはパスワードが正しくありません」が表示される |
| F-02 | ログインしてからブラウザを閉じ、開き直す | ログイン状態が保たれている |
| F-03 | ログアウトしてからブラウザの「戻る」を押す | ログイン画面が表示され、投稿などのデータは見えない |
| F-04 | 未ログインで `/posts/1` を開き、ログインする | ログイン後に `/posts/1` が表示される |
| F-04 | 未ログインで API（例：`GET /api/posts`）を直接呼ぶ | 401 が返る |
| F-04 | CSRF のトークンを付けずに `POST /api/posts` を呼ぶ | 403 が返り、投稿されない |
